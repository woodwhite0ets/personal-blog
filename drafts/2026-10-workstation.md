# 给 AI 修工地：一台旧服务器上到底跑着什么

> 24 核的老 Xeon、62G 内存、两块盘，常年开着。这篇讲它凭什么不是一台"折腾着玩的服务器"。

## 凌晨三点的那行字

每天 3:02，这台机器会自己醒一次。

它把 `/data/knowledge` 下的 52 条知识逐条打开，抽掉代码块，扫描正文里出现的每一个路径、端口、systemd 单元名和 docker 容器名，然后挨个去探：文件还在吗、端口有人听吗、这个 unit 还存在吗。跑完写一行字进日报。

昨天那行是这样的：

```
合并 0 条 · 标记过时 0 条 · 归类 0 条 · 引用体检 197 处 · 失效 4 处（4 条受影响）· 22s
```

4 处失效，分布在 4 条知识里。其中一条还在教人查 `dashboard.service`——那个服务我半个月前就删了，面板代码也一起删了。另一条让人去 `/data/transfer/README-cross-os.md` 找一个说明文件，而那个文件在共享盘整理时被我移进了 `文档/` 子目录。

如果没人管，这类知识会一直躺在库里，被检索命中，被当成"权威结论"喂给 AI。它不会报错，只会让我在某些时刻做出基于旧地图的判断。

所以我把这件事做成了机器自己的活。修完那 4 条之后，同样是这条命令，今天返回 0。

我给这台机器的定位很简单：**它不是跑服务的服务器，是给 AI 修的工地。**

## 机器上有什么

```

       │                    编码 agent（轮流上）                  │
       └───────────────────────┬────────────────────────────────┘
                               │ MCP
                    ┌──────────┴──────────┐
                    │      mcp-proxy      │  把知识库/记忆/技能
                    │       :19090        │  统一成一套工具
                    └──┬───────────────┬──┘
            知识库 ────┘               └──── 记忆层
        (52 条 md，本地向量检索)     (会话痕迹，L0/L1)
                               │
       ┌───────────────────────┴────────────────────────────────┐
       │  llama.cpp ×3      对话 8092 · 嵌入 8090 · 重排 8091    │
       │  Forgejo + CI      提交即跑 ruff / semgrep             │
       │  Caddy · frp       对外只走出站隧道，零入站端口         │
       │  systemd ×5 timer  巡检 / 索引 / 同步 / 清理            │
       └────────────────────────────────────────────────────────┘
```

图上没有数据库、没有容器编排、没有监控大盘。不是不想要，是这台机器只值这么多。

### MCP 网关：一个入口

最早每个 AI 客户端都要单独配一遍：知识库怎么连、服务器怎么查、技能从哪读。换个客户端就重配一次，配错了还不知道错在哪。

现在这些收在一个进程后面，通过 MCP 协议统一暴露。客户端只认一套工具名：查知识、读文档、看服务器状态、跑受控命令、调本地模型。底下实现换过几次，它们不用改任何配置。

网关本身是个 Go 写的反向代理，配置文件里挂了三个上游：知识库、记忆、技能。左边进来的请求按路由分发，右边挂的上游挂了就自动摘掉，不拖累其他路由。

### 知识库：手写的，机器维护的

52 条 markdown，目录按项目分，每篇带 frontmatter：`title` / `scope` / `project` / `updated` / `status` / `tags`。

检索走本地向量：`bge-m3` 做嵌入，1024 维，落盘成一份 JSON 索引；查询时先向量粗排 20 条，再用 `bge-reranker-v2-m3` 重排取 5 条。冷启动加载索引 1.6 秒，热查询 200 毫秒。

这套东西的价值不在"能搜到"，在于**搜到的东西是可信的**。所以每条有 `status`：`active` 是现行结论，`superseded` 是被新结论取代的历史版本，`stale` 是引用已经失效的。检索默认只给 `active`，要看演进史才把它们放出来。

### 模型：三个实例，各有各的岗

一张 RX580（矿潮退下来的），llama.cpp 用 Vulkan 后端，`-ngl 99` 全量卸载到显存：

- 8092 跑对话模型，7B，问答和改写够用
- 8090 跑 `bge-m3`，嵌入
- 8091 跑 `bge-reranker-v2-m3`，重排

后两个是知识库的底座。它们不像对话模型那样有存在感，但一晚上没人用也不花钱，这是关键。

### 定时器：五个，各管一段

`ci-poll` 每两分钟捞一次提交，`alerts` 看磁盘和服务健康，`code-reindex` 每天 0 点重建代码向量索引，`reap` 清理冻结的 agent 会话，`thesis-sync` 每五分钟把毕设目录同步到共享盘。

加上晚上 3 点的知识整理，一共六个。它们不需要我记得，只需要 `systemctl --user list-timers` 还能列出它们。

## 决定一：模型自己跑

云端模型没少用，但分工得说清楚。

给 52 条知识写一句话摘要、把 GitHub 项目描述翻成中文、给候选回复打标签——这些是**量大、单价低、容错高**的活，本地 7B 就够。实测 120 条中文摘要，并发 4，140 秒跑完，零成本。

审代码、判断"这次改动会不会破坏权限校验"、设计派发策略——这些是**量小、单价高、错了代价大**的活，必须上强的。

判断标准只有一条：**这件事值不值得花那份钱**。

中间还有个不显眼的设计：本地模型的输出不可靠，必须做确定性收敛。7B 写中文摘要经常超长、写成两句、括号里塞一长串枚举、中英文粘在一起（`ClaudeCode` 这种）。这些不能靠再问一遍模型解决——我写了一个纯规则的后处理：去掉括号补充、只保留第一句、按逗号累加到 36 字、中文之间去空格但保留中英文之间的空格。处理后平均 25 字，这才敢上线。

## 决定二：记忆分两层

早期我把所有东西都往知识库里塞，结果是检索一次能捞出五条互相矛盾的东西，还得自己判断哪条最新。

现在分两层：

- **结论层**：`/data/knowledge` 那 52 条。手工策展，一条一个判断，带状态和日期。AI 可以直接引用。
- **痕迹层**：会话自动落库，谁在什么时候说过什么。只当线索，不能当结论。

两层的差别不是存储方式，是**可信度**。混在一起用，等于让 AI 拿着聊天记录当规范。

这条线也决定了写入的规矩：`kb_write` 现在会校验结构——正文不足 80 字、没有二级小节、开头没有一段结论，直接拒绝并返回骨架。不是洁癖，是因为检索是靠这几段话命中的，写成流水账以后就再也搜不出来了。

前几天我自己被这条规则拦了一次：写"首页板块顺序"那条时没加小节标题，工具直接报错让我按骨架重写。

## 决定三：任务分档派

一个任务进来，先看它值多少钱。

侦察、检索、汇总、读大文件找线索，派便宜档。写代码、跑测试、改配置，派中档。架构判断、安全审计、多方案对比，才用强的。强档有预算护栏，超出就停。

档位不是靠我临场记，是写成文件的：派发权限分级（哪些能自主、哪些必须问人）、档位映射（什么任务给哪个模型）、拆解模板、成本上限。AI 每次开会话先读这份规则，不靠我提醒。

再往下一层还有个冷热分层：常用的 agent 保持热配置，不常用的冻结，冻结太久的直接回收。会话目录不加管控，半年就能堆出几十万个文件。

## 决定四：成本有护栏

花钱的地方只有两处：云端模型的 token，和电费。

前者按 provider 记账，贵档调用要在回复里写明理由；后者没细算，一台常年开着的旧服务器，一晚上跑几次嵌入，估计比路由器多几瓦。

护栏的作用不是省钱，是**让"要不要用贵的"变成一个显式决定**，而不是顺手就用了。

## 踩过的坑

**日期会差一天。** 数据库里的 `DATE` 字段被驱动读成 `Date` 对象，`toISOString()` 在 UTC+8 下会折回前一天。表现是榜单日期、体检结果全错位一天。它看起来很正常，这才是麻烦的地方。连接池加一行 `dateStrings: ['DATE']` 才好。

**`rank` 是 MySQL 8 的保留字。** `SELECT rank_no AS rank` 直接语法错误，得写成 `` AS `rank` ``；塞在 JS 模板字符串里还要再转义一层反引号，转错一次就要查半天。

**服务从 shell 挪到 systemd，权限就没了。** GPU 服务改成用户级 unit 之后起不来，日志里看不出原因。查下来是设备节点权限：用户在 `video`/`render` 组里，但设备 ACL 没给到这个会话。补一条 ACL 才通。

顺带把所有 `nohup` 起的进程都删了——会话一断就被 SIGKILL，日志也没落下，这种"看起来在跑"的进程比不跑更糟。

**HuggingFace 在腾讯云那台机器上不通。** 想抓 daily papers 当数据源，`curl` 回来 `000`。GitHub API 和 HN Algolia 通，所以 AI 榜最后只用了这两家。

**扩展返回的消息不会进对话。** 给 pi 写自动注入知识库的扩展时，`before_agent_start` 返回一条 message，代码跑到 return 了，对话里却没有。翻了类型定义才发现那条消息的类型是 `CustomMessage` 的子集，得用 `customType` 而不是 `role`。最后还是改成往 system prompt 里追加才生效。

## 现在

- 知识库 52 条，197 处引用，体检 0 失效
- AI 一次调用能拿到一个主题的全貌：相关条目正文 + 演进时间线 + 冲突提示
- AI 项目榜每天 08:00 自己更新：抓 GitHub、本地模型写中文、服务器算日增、12 条上榜
- 这台机器上 22 个项目，6 个定时器，0 个入站端口

要验证的话，一条命令就够：

```bash
node /data/knowledge/_tools/kb-verify.mjs
```

它会把每条知识里提到的路径和服务挨个探一遍。如果哪天它开始报错，说明我该去干活了。
